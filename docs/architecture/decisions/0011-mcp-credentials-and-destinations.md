# ADR 0011: External encryption keys and operator destination policy

Accepted 2026-10-31. Bearer credentials are write-only registration input. PostgreSQL stores AES-256-GCM ciphertext, a fresh 96-bit nonce, and an external key ID. Additional authenticated data binds organization, credential UUID, and key ID. The versioned keyring is mounted read-only outside Git and the database. Retain old keys during rotation, change the active key ID for new writes, and replace an integration credential through a new configuration revision. Lost keys are not recoverable from the database. Never print generated values or commit local environments.

Operator policy supplies exact canonical endpoint URLs. Administrators dynamically register compatible servers within that policy without changing host/frontend code. The adapter validates and resolves every request, rejects unsafe addresses, and pins the validated IP at socket lookup. HTTPS is required in production. Explicit development policy permits only named allowed HTTP endpoints, including the two container peers. Metadata/link-local, redirects, userinfo, query credentials, fragments, malformed URLs, and unapproved targets remain denied. Original hostname is retained for TLS verification. No remote schema references are fetched.

The bridge has a separate generated service credential and no source DB access. Each native server has its own bearer credential and its existing source reader credential. Servers reject unsolicited Origin headers and unknown Host values. Tokens never belong to browser storage or normal response JSON. OAuth is outside this bounded bearer-only phase.

# REST execution security

The platform is tenant/governance authority; REST gateway is an isolated data plane, not an arbitrary HTTP proxy. [ADR 0013](decisions/0013-isolated-rest-egress.md) and [contract/lifecycle](REST_CONNECTORS.md) specify the boundaries. Tests and actual evidence are linked in [verification](../development/PHASE_5_VERIFICATION.md).

## Destination and transport

Both backend and runtime require an operator entry: `scheme://hostname:effectivePort/basePath|tls` or exact local `|dev`. URLs must have an ASCII DNS name, approved port/base path, no IP literal, userinfo, query, fragment, percent escape, backslash, trailing dot, relative path or scheme ambiguity. No root/operation server suggestion expands policy. HTTPS default trust and hostname verification are mandatory outside explicit development HTTP entries. No insecure TLS checkbox or arbitrary trust material is supplied by an administrator.

Runtime validates every DNS answer, not just its first address: reject unspecified, loopback, link-local, multicast, metadata, CGNAT, reserved/documentation/benchmark, IPv4-mapped IPv6, scoped IPv6 and transition ranges; private IPv4/ULA must match operator CIDRs. DNS workers/queue are each four and calls have a 1.5-second lookup bound. JDK resolver caching can apply. The first safe address set is pinned for gateway lifetime; an unexpected set change fails closed and requires operator-reviewed restart. Every connection rechecks the full set and connects using an already checked `InetAddress`. TLS wraps that socket with original SNI/hostname and HTTPS endpoint identification. It does not perform an unvalidated second HTTP-client DNS lookup.

The strict JDK HTTP/1.1 transport has no proxy, automatic redirect, retry, cookie jar or retained source socket pool. It constructs only GET with fixed Host/Accept/Accept-Encoding/Connection and configured auth header. Percent-encode components once; path values cannot contain traversal, slash, backslash or percent encodings. Arguments cannot inject headers, bodies, methods, origins or unapproved query keys. 3xx is an explicit error before any Location connection or credential forwarding. Duplicate/ambiguous headers/framing, chunk extensions/trailers, unsupported transfer/content encodings and non-JSON fail closed. This deliberately sacrifices some API compatibility for a small testable framing subset.

Limits: eight global/two per connector operations; 2-second TCP connect, 3-second socket/handshake/read idle, 10-second overall operation with socket closure; no retry. Header budget 16 KiB/64 entries; 256 KiB encoded body and independently 256 KiB after gzip; JSON depth 24/20,000 nodes, at most 1,000 array elements during validation and 100 returned array items; cell strings 8,192 characters; arguments 8 KiB/16 parameters/1,024-character scalar request values. Limit violations are failures, not silent empty responses. Larger valid array responses can be explicitly truncated after validation. Cancellation cannot undo a GET already received remotely.

## Network reality

`ecosync-rest_sources` is internal and contains only REST gateway, independent Supplier and Partner APIs. Supplier retains its separately owned original network; gateway does not join it. Backend joins REST control, metadata/default and existing opt-in control networks, never REST/database/movies source networks. REST gateway has no host port and does not join database control/source networks. The database gateway has no REST source-network membership. Key mounts are read-only; processes run without capabilities, with read-only root filesystems, PID/memory/CPU limits.

Compose is not a per-port firewall: any process on a network can address other members, and internal networks alone do not isolate a compromised gateway from its control-plane peer or prevent host-initiated access. There is no production public egress route in this local profile. Real production egress requires independent network firewall/proxy controls, secure control transport and operator-managed TLS trust. Application URL policy alone is never described as complete network egress isolation. Host/Docker daemon compromise is outside this boundary.

## Credentials and audit

NONE, Bearer and configured header API key only. Never query credentials, Basic, cookies, OAuth flows, client certificates or user-controlled arbitrary headers. Header names cannot replace framing, Host, Authorization, forwarding or browser/security headers. Tokens are visible ASCII without whitespace/controls and bounded to 16–512 characters. A gateway compromise can still expose admitted credentials in memory.

Backend alone reads the external versioned AES-256 keyring. REST uses a separate ciphertext table, fresh 96-bit nonce, AES-256-GCM and `ecosync-rest/org/credential/keyId` authenticated associated data. Neither database-purpose nor another tenant's copied ciphertext decrypts as REST. Key IDs preserve retained old keys during rotation. Ordinary APIs/UI never return stored secrets; input secret state clears after save success/failure. Gateway gets scoped secret material only over authenticated authority callback; source sockets are closed after each operation. No raw source bodies, complete arguments, credentials, headers or HTTP exception chains enter history/logs. Controlled error codes classify auth, forbidden/not found, network/TLS/timeout, non-JSON/schema, redirect and size failures.

## SDK and dependency review

Existing Java SDK 2.1.0/Boot 4.1.2/AI 2.0.2/Node 24.22.2/frontend pins and container digests are retained. No new HTTP/OpenAPI runtime dependency is introduced. New build-only `org.codehaus.mojo:build-helper-maven-plugin:3.6.2` adds the same pure contract sources to the gateway build, avoiding two divergent validators. [Official goal](https://www.mojohaus.org/build-helper-maven-plugin/add-source-mojo.html), [requirements](https://www.mojohaus.org/build-helper-maven-plugin/plugin-info.html), [release/source](https://github.com/mojohaus/build-helper-maven-plugin/releases/tag/3.6.2), and [published advisories](https://github.com/mojohaus/build-helper-maven-plugin/security/advisories) were inspected 2026-11-05; no project advisory was listed. JDK 21/Maven 3.9.16 builds verify actual compatibility. This is a point-in-time review, not a complete supply-chain audit.

[Official SDK advisories](https://github.com/modelcontextprotocol/java-sdk/security/advisories) were rechecked: transport Origin/Host checks, authenticated private access, finite request/session admission, bounded responses and sanitized handler failures remain required. We use stateful servlet transport, reject every unsolicited Origin, bind sessions to signed context, and never expose raw handler exception chains. Earlier SDK hardening evidence remains in Phase 3/4. [JDK TLS parameters](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/javax/net/ssl/SSLParameters.html) and [HTTP framing RFC 9112](https://www.rfc-editor.org/rfc/rfc9112.html) inform the actual socket tests. Do not infer support for later MCP revisions or production readiness.

GET-only is a method restriction; an external owner must ensure its approved GET operations have read-only semantics. EcoSync cannot undo side effects implemented incorrectly by a remote API.

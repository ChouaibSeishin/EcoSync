# Managed database security

This phase has two independent authorization boundaries: browser session/CSRF with current tenant membership, then private authenticated MCP with verified delegation and fresh platform authority. No platform administrator bypasses membership. INTEGRATION_ADMIN manages connections/scopes; USER needs an explicit current table/column grant; AUDITOR never executes reads. React controls are convenience only.

The platform signs Ed25519 assertions with exact issuer/audience, actor/org, connector/revision, action, table, canonical argument hash, execution ID, issue/expiry and unique assertion ID. Maximum lifetime is 30 seconds. Transport has a separate generated gateway bearer; an ordinary tool argument cannot replace either identity. Signature/time/audience/claim checks precede protected transport handling. Every listing and call consults current persisted scope; calls also require the RUNNING audit execution and exact approval fingerprint. A tools/call assertion is single-use in the gateway. Sessions are bound to its assertion hash, not reusable actor authority. Missing/malformed/expired/forged/wrong-audience assertions, wrong service identity, unsolicited Origin and unknown Host are denied.

The global server catalog holds only neutral generic schemas, never tenant table/column/connection names. Per-request filtering is not the execution gate: a hidden tool called by name must still fail current authorization. Broadcast SDK catalog notifications are disabled for the filtered production catalog. No client sampling/roots/model/global callback catalog or public MCP host port exists.

Database credentials use fresh-nonce AES-256-GCM, a distinct database purpose and organization/credential/key-ID authenticated data, an external versioned keyring and an opaque internal reference. Only backend can decrypt; gateway has no AES keyring or signing private key. It receives scoped connection material through the private authenticated authority callback only after governance checks. Existing ciphertext remains tied to old key IDs during rotation. Credentials are write-only at the normal API/UI, omitted from revision/audit/result DTOs and redacted from object string representations. There is no plaintext credential table, URL credential or raw exception response. SDK/driver/bind payload logging is disabled; history retains correlation/actor/revision/outcome, not arguments/results.

Operator policy fixes exact typed destinations. It refuses raw JDBC URLs/properties/classes, query credentials, system schemas and arbitrary host/port expansion. Both control plane and gateway validate tuples. Gateway checks all DNS answers at each admission/socket, pins a validated address while retaining original TLS hostname, rejects metadata/link-local/loopback/reserved targets, and allows private addresses only within explicit operator CIDRs. DNS lookup callers and workers are bounded; changed address sets fail closed. Production TLS verifies certificate trust and hostname. Development plaintext/public-key retrieval is isolated to named fixture targets. Never solve a TLS failure by disabling verification for production.

The backend stays outside the source network. Only the deliberately trusted gateway joins source/control, and only the public delegation key is mounted there. Source systems remain owned separately; separate gateway reader accounts receive business-table SELECT without write/DDL/admin/history privileges. Session read-only flags, PostgreSQL statement/lock deadlines, MySQL optimizer deadlines, forbidden multi-statement/local infile/deserialization options and prepared values provide additional defenses. Database grants are tested with read-only flags disabled as well as through the managed path.

JDBC metadata is bounded to permitted schemas and TABLE objects, excludes migration histories, fetches no sample rows, and snapshots a fingerprint for explicit review. Only approved names from that metadata reach the dialect quoting function. Literal filter values never become SQL, operators come from a closed set, and raw SQL/functions/joins/writes are rejected. The backend independently validates the structured query before MCP; gateway validates again before opening/dispatching source resources. Result rows, streamed text cells and bytes have independent limits with explicit truncation/partial states.

Governance changes fence persisted admission before pool cleanup. Resource retention and MCP visibility are separate; DRAFT inspection can use bounded resources without publishing data tools. Pools bind current revision and approval-set epoch; startup/periodic reconciliation retires stale resources even after a lost immediate cleanup call. In-flight operations carry generation/cancellation fences, reauthorize before SQL and results, and the backend compare-and-sets completion under its local governance lock. Cancellation cannot recall a completed external read. One backend replica is supported; distributed locks/admission are not implemented.

Private verification counters/holds exist only behind an explicit development verification flag, use the internal bearer, and are absent from MCP discovery. Normal deployment returns 404 for those observer functions. Holds are bounded, delay real already-authorized work before SQL, recheck authority afterward, and never synthesize source rows. Tests identify that instrumentation separately from actual database timeout/schema-change tests.

Residual limits: the trusted gateway necessarily handles plaintext connection material in memory; a compromised gateway/host can act with source reader credentials. Private development control traffic uses HTTP, and production operators must secure transport, trust stores, keys and backups. Authorized source data can still be sensitive or incorrect. Point-in-time dependency audits, local Docker and CI are not production certification or a performance benchmark.

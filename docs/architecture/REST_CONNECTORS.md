# Dynamic REST connectors

Phase 5 adds a distinct REST authority module, V5 metadata migration, isolated `rest-gateway/` and React **Integrations → REST APIs**. Implementation verification is tracked in [Phase 5 verification](../development/PHASE_5_VERIFICATION.md); this document is not acceptance evidence. [ADR 0013](decisions/0013-isolated-rest-egress.md) records the design.

The generic path is browser session/CSRF → tenant registry → official SDK MCP client → private REST gateway → independent HTTP source. Backend never constructs source requests. The gateway has no platform database connection, AES keyring, signing private key or database source-network membership. Supplier Bearer authentication and Partner header API-key authentication use exactly the same registry/import/runtime, without compiled business adapters.

## Contract subset

JSON uploads/paste only; OpenAPI `3.0.x` and `3.1.x` (numeric patch), not 3.2, YAML, URL imports or full OpenAPI conformance. Strict duplicate keys/trailing JSON rejection. Local map JSON Pointers support `~0`/`~1`; external/relative/percent-encoded, unresolved, cyclic or `$ref` siblings are rejected across the whole document. No network or filesystem reference fetch exists. Semantically identical JSON formatting/key order has the same SHA-256 document fingerprint; contract content changes alter it.

Default configurable import ceilings: 256 KiB UTF-8 document, 64 paths, 128 operations, 20,000 expanded nodes. Hard ceilings are 1 MiB, 128 paths, 256 operations, 50,000 expansion nodes. Reference expansion is charged incrementally against a conservative 1 MiB escaped-text budget before serialization (so reference amplification cannot allocate an oversized output buffer); expanded JSON is also capped at 1 MiB, per-operation normalized review at 32 KiB and total operation review at 512 KiB. Original JSON depth 24/20,000 nodes; reference expansion depth 24; schema depth 8/256 schemas; 64 object properties, 16 parameters, 64 enum values. Configuration names: `ECOSYNC_REST_IMPORT_BYTES`, `IMPORT_PATHS`, `IMPORT_OPERATIONS`, `IMPORT_NODES` under the same `ECOSYNC_REST_` prefix. Upload envelope limit 1 MiB. Malformed IDs, duplicate explicit IDs and ambiguous templated paths fail import. Missing IDs get a deterministic method/path SHA-256 alias; collisions fail closed.

Supported operations: GET, no body; ASCII literal paths with full-segment `{parameter}` placeholders; scalar string/integer/number/boolean path/query parameters; path `simple`, query `form` serialization. No duplicate names/parameter overrides, header/cookie parameters, parameter arrays/objects, `allowReserved` or `allowEmptyValue`. Required path declarations must exactly match unique placeholders. Operation/path server overrides and callbacks are unsupported. Root `servers` are untrusted suggestions and never used for routing.

Responses require explicit numeric 2xx status entries and exactly `application/json`, with a supported schema. No wildcard/default success schema, binary, XML, multipart, request bodies, webhooks, callbacks, alternative hosts or write methods. Unsupported operations stay visible with a reason and cannot be approved. Unsupported schemas never become permissive executable schemas.

Schema subset: explicit object/array/string/integer/number/boolean types, properties/required, boolean additionalProperties, recursive array items, scalar enums, inclusive numeric bounds, string/item length bounds, date/date-time/UUID formats and numeric format annotations. OAS 3.0 boolean nullable and OAS 3.1 `[type,"null"]` are normalized separately. Nullable-enum combinations are unsupported. Unknown assertion keywords, arbitrary patterns, compositions, conditional schemas, unevaluated/additional schema maps and dynamic references are rejected. Patterns are anchored literal/fixed character-class repetitions, plus the finite decimal-money pattern needed by the original Supplier contract; arbitrary regex execution is not supported. Descriptions/examples/default/readOnly/writeOnly/deprecated are annotations; defaults are validated before applying. Runtime limits still apply to permissive additional properties and absent schema maxima.

## Persisted governance

`rest_connector` holds tenant identity/state/health, `rest_configuration` immutable destination/auth/document/config revisions, `rest_operation` immutable normalized operation metadata and opaque IDs, `rest_approval` role/fingerprint-bound grants, `rest_credential` purpose-separated ciphertext, `rest_event` sanitized history. Runtime has SELECT/INSERT, no UPDATE, on configuration/operation tables. Composite organization foreign keys prevent cross-tenant configuration references.

Lifecycle: DRAFT → explicit inspection → INSPECTED → selected GET/role approval → APPROVED → successful approved authentication test → ACTIVE. Import/review perform no protected source request. Authentication testing executes one selected **already approved** GET and discards its data; an unapproved contract cannot use a test button to bypass execution approval. This deliberately places approval before protected authentication testing. Tests do not activate. The list shows at most 128 recent records and hides revoked records unless explicitly requested; immutable history remains available. Revoked state cannot be downgraded through disable/inspect; recovery requires a new revision. Disable/revoke stale grants; revoke also revokes the credential. Revision creates new operation identities and fingerprints, stales earlier grants and requires fresh inspection/approval/testing/activation. An unchanged active approval is retained across process restart, never newly granted by restart.

INTEGRATION_ADMIN manages connections and grants; USER needs its own current operation grant; AUDITOR cannot execute. Authority rechecks live membership/role/revision/state/credential/approval and RUNNING execution at gateway admission, dispatch, result release and backend completion. Disabled/revised/revoked/cancelled work cannot commit a late successful response. One backend replica is supported.

## MCP and explorer

Neutral tools: `rest_describe_operation` and `rest_invoke_operation`. Arguments are opaque connector/operation UUID, exact revision, and a typed `parameters` object. They do not accept a URL, method, header or request body. The global catalog contains no API names or tenant operations. Request filters and handlers independently consult current authority. No global list-change broadcasts; refresh discovery explicitly. Official Java SDK 2.1.0 is retained, and only tested protocol `2025-11-25` is claimed. Existing native dual-era MCP behavior remains separate.

REST uses its own Ed25519 keypair/audience `ecosync-rest-gateway`, short-lived (≤30 seconds) assertion, separate internal service bearer, and single-use invocation ID. Claims bind issuer, actor, organization, connector/revision, action, opaque operation, execution, canonical arguments hash and issue/expiry/JTI. Database gateway cannot accept these assertions.

Manual explorer responses carry `untrusted`, source status, retrieval time and correlation. History stores actor/org/revision/operation/outcome/duration; never query arguments, raw responses or credentials. Arrays are bounded to 100 returned items in aggregate, with explicit truncation/partial flags. Source pagination remains API-specific contract parameters; no fabricated continuation token is generated. A truncation result can contain the source page metadata from the larger validated response; callers must choose a smaller contract page size when they need exact continuation.

No LLM, models, chat, semantic mapping, joins, automatic execution or write operations are introduced.

Stable SDK exposes runtime add/remove and request-time list filters; filtering alone does not authorize calls. Explicit tools capability configuration avoids the known inferred-empty-capability mutation failure. Spring callback scanning is not the runtime registry. SDK 2.2.0-M1 has a modern server but is prerelease and upgrades Reactor; it is not selected. The stable production target remains Java 21 / Boot 4.1.2 / Spring AI 2.0.2 / SDK 2.1.0, with no claim of modern server support.

The disposable proof runs a real Java servlet MCP endpoint, the existing official TypeScript 2.4.0 client and a separate file-backed HTTP authorization authority, entirely inside a pinned Linux container with network disabled. It uses independent transport authentication and Ed25519 signed short-lived delegated assertions. Proof tests are distinct from later PostgreSQL/MySQL connector tests. The initial run passed nine checks but stalled on graceful cleanup of open servlet streams; proof termination is now bounded before testing restart. The next ten-check run passed. An extended mutation-failure check initially expected absent-tool removal to fail; actual SDK behavior is idempotent success (200), while null registration fails (500). That expectation was corrected to the observed behavior without weakening authorization checks.

# Phase 3 acceptance

Observation date: 2026-10-31 UTC. Authorized scope is native remote MCP only. Checkpoints A-G have passed locally. Checkpoint H is in progress: the native CI job and final branch-head verification must succeed before final acceptance is claimed. No later phase is authorized or started.

The platform retains Java 21, Boot 4.1.2 and the Spring AI 2.0.2 BOM. A replaceable Java client port calls an authenticated isolated official TypeScript MCP client/core 2.4.0 service. This adds a Node process, authenticated network hop and deployment/resource responsibility; no measured performance benefit or full MCP conformance is claimed. Stable Java SDK 2.1.0 cannot act as a modern client, and the server milestone/AI RC do not safely solve that gap. See [the decision and actual matrix](../architecture/MCP_COMPATIBILITY.md).

The local stack check measures business-tool SQL admissions at each server's prepared-query dispatch, excluding independent readiness probes. Denied calls did not reach that point; positive calls incremented it and produced actual source data. Controlled-port registry tests isolate authorization/races using real PostgreSQL and crypto; they are explicitly separate from real official-peer and source-server interoperability evidence.

Known limits: bearer-only controlled Streamable HTTP and tested Tools for 2025-11-25/2026-07-28; bounded JSON Schema subset; no OAuth/STDIO/resources/prompts/tasks/roots/sampling/elicitation UI; single backend replica, in-memory HTTP sessions/throttling; no automatic tool-call retry; development HTTP and Vite server; external-key backup/rotation are operator responsibilities. Native demos do not advertise output schemas, so declared-output validation is exercised with official peers rather than invented source schemas. The additional Node process/hop has not been benchmarked. The exact temporary minimatch 11.0.1 security override is outside the original lint dependency major range; repo lint file coverage/types/build/tests/audit passed, and it must be revisited when upstream packages adopt the fixed version. Point-in-time audits are not an exhaustive security assessment.

Phase 4 starts by inspecting the accepted native registry/client/security contracts, researching the then-current gateway and JDBC dependencies, and designing separately governed PostgreSQL/MySQL connector registration, schema allowlists and bounded prepared read operations through a managed MCP gateway. Preserve native MCP registration and source isolation. Phase 4 implementation has not begun. Supplier REST onboarding remains Phase 5; AI selection/chat remains Phase 6; general joins/mapping management, benchmark execution, Kubernetes/Argo and registry publishing are absent.
